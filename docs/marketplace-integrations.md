# Marketplace integrations

## First stage: unified feed and FL.ru

The application reads `public/data/jobs.json` and merges its normalized `jobs` array into the existing feed. The file is generated by `scripts/fetch_marketplace_feed.py`.

- **FL.ru:** public RSS endpoint `https://www.fl.ru/rss/all.xml`; imported by GitHub Actions every 30 minutes.
- **Kwork:** no supported public jobs API/RSS feed confirmed. Do not automate private/mobile endpoints or scrape authenticated pages.
- **Freelance.ru:** no supported public jobs API/RSS feed confirmed in this review. Its Telegram bot is a user-facing notification channel, not a documented feed API.
- **Upwork:** official GraphQL API supports marketplace job search, but API-key approval and OAuth credentials are required. Store secrets only in a backend or GitHub Actions secrets; never in the browser bundle.
- **Freelancer.com:** official developer API exists. API application credentials and an authorized token are required before enabling project search.

## Normalized job record

`id, source, sourceLabel, title, company, description, budget, low, type, level, category, posted, publishedAt, duration, skills, url`.

The current FL.ru adapter fills the fields available in RSS and uses neutral placeholders for data the feed does not provide. Deduplication is by normalized project URL.

## Deployment and security

GitHub Pages is static hosting. It must only receive the sanitized JSON snapshot, never API secrets or OAuth tokens. The scheduled workflow fetches the public RSS source and commits a changed snapshot; the Pages deployment workflow then publishes it.

Before activating the other marketplaces, obtain their official credentials/approval and add server-side adapters with rate limiting, retries, and source-specific terms-of-service checks. No authenticated scraping, CAPTCHA bypass, or private mobile API usage is implemented.
